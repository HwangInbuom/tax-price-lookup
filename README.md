# 주소 → 공시가격 자동조회 백엔드 + 통합 데모 (프로토타입)

사용자가 주소를 입력하면 (1) 카카오 주소검색 API로 PNU(필지고유번호)를 만들고,
(2) 브이월드(V-World) 공동주택가격 API로 공시가격을 조회해서 돌려주는
FastAPI 백엔드입니다. 이 서버가 완성되면, 계산기 프론트엔드에서 공시가격을
수동 입력하는 대신 주소 한 줄로 자동 채우기가 가능해집니다.

**2026-09-17 업데이트**: 실제 키 2개(카카오, 브이월드)를 발급받아 직접 호출해보고
받은 응답을 기준으로 전체 코드를 검증 완료했습니다. 더 이상 placeholder가 아니라
바로 실행되는 코드입니다.

## 현재 상태

- `backend/pnu.py` — 완성. 주소 → PNU 변환.
- `backend/price_api.py` — 완성. PNU(+동/호) → 공시가격 조회. 실제 응답으로 검증됨.
- `backend/trade_price_api.py` — 완성. 지번(PNU 본번/부번) → 최근 N개월 아파트 매매 실거래
  내역 조회 (양도소득세 참고 시세용). 실제 응답으로 검증됨.
- `backend/main.py` — 완성. `/lookup?address=...&dong=...&ho=...`,
  `/trade-price?address=...&months=...` 엔드포인트. `/lookup`은 올해·작년 공시가격을
  한 번에 조회해서 같이 내려줍니다 (아래 "올해·작년 공시가격 한 번에 조회" 참고).
- `backend/.env` — 이미 발급받은 실제 키 3개(카카오, 브이월드, data.go.kr)가 채워져
  있어서 바로 실행 가능합니다.
- **아파트/연립주택(공동주택)만 자동조회됩니다.** 단독주택은 공식 오픈API가 없어서
  자동조회가 안 됩니다 (프론트엔드에서는 "부동산공시가격알리미에서 직접 조회 후
  수동 입력" 경로를 함께 제공해야 합니다).
- **한 아파트 단지 안에 세대(동/호)가 수백~수천 개일 수 있고, 세대마다 공시가격이
  다릅니다.** 그래서 주소만으로는 부족하고, 사용자가 "동/호수"까지 입력해야 정확한
  공시가격이 나옵니다. `dong`, `ho` 파라미터를 안 넣으면 여러 세대가 섞여서 나오고,
  응답에 `needs_unit_disambiguation: true`가 표시됩니다 — 프론트엔드에서 이 신호를
  보고 "동/호수를 입력해주세요" 라고 다시 물어보게 만들면 됩니다.

## 실제로 사용하고 있는 API (검증 완료)

| 용도 | 제공처 | 실제 호출 주소 |
|---|---|---|
| 주소 → 법정동코드/PNU | 카카오 로컬 API | `https://dapi.kakao.com/v2/local/search/address.json` |
| PNU(+동/호) → 공시가격 | 브이월드(V-World) 국가중점데이터 API | `http://api.vworld.kr/ned/data/getApartHousingPriceAttr` |
| 지번(PNU 본번/부번) → 최근 실거래가 | 국토교통부 (data.go.kr 자체 호스팅) | `https://apis.data.go.kr/1613000/RTMSDataSvcAptTradeDev/getRTMSDataSvcAptTradeDev` |

공공데이터포털(data.go.kr)에서 "공동주택가격"으로 검색했을 때 나오는 오픈API는
data.go.kr 자체 서버가 아니라 **브이월드로 연결(LINK)되는 API**라서, 실제 인증키도
브이월드에서 별도로 발급받아야 한다는 점이 이번에 확인됐습니다 (data.go.kr 활용신청은
불필요했습니다 — 브이월드 인증키 발급만으로 충분합니다).

반면 "아파트매매 실거래가 상세 자료"는 **data.go.kr가 직접 운영하는 API**라서, 상세
페이지에 들어가는 순간 "개발계정"이 자동으로 즉시 승인되어 있었습니다(별도로 "활용신청"
버튼을 누를 필요 없음, 마이페이지에서 인증키만 확인하면 됨). 응답은 JSON이 아니라 XML
입니다.

## 1단계: API 키 발급 받기 (이미 완료하셨다면 2단계로)

### (A) 카카오 REST API 키

1. https://developers.kakao.com → 로그인 → "내 애플리케이션" → 앱 추가
2. 앱 클릭 → 왼쪽 메뉴 "플랫폼 키" (또는 "앱 키") → **REST API 키** 복사

### (B) 브이월드(V-World) 인증키

1. https://www.vworld.kr → 회원가입/로그인
2. 상단 메뉴 "오픈API" → "인증키 발급" (마이포털 > 나의 오픈API > 인증키관리)
3. 신청서 작성 — 서비스URL은 테스트 단계면 `http://localhost:8000` 처럼 임의로 입력해도
   되고, 서비스분류/활용API는 "국가중점API"가 포함되도록 체크
4. "발급" 클릭 → 화면에 나오는 인증키 복사

### (C) data.go.kr "아파트매매 실거래가 상세 자료" 인증키

1. `www.data.go.kr` 검색창에 "아파트매매 실거래" 검색 → **"국토교통부 아파트 매매
   실거래가 상세 자료"** 클릭
2. 이 API는 들어가는 순간 "개발계정"이 자동 승인되어 있습니다 — 별도로 누를 버튼이
   없습니다
3. 왼쪽 메뉴 "마이페이지" → "데이터활용" → "Open API" → "활용신청 현황" → 방금 그
   항목 클릭 → **"일반 인증키(Decoding)"** 복사

## 알아두어야 할 것들

- **동/호 입력이 필요합니다.** 실제 서비스에서는 사용자가 주소를 입력한 뒤, "동/호수"를
  추가로 입력받는 화면이 꼭 필요합니다 (예: 카카오 주소검색으로 나온 결과에 이어서
  "104동 402호"처럼 별도 입력창을 두는 방식).
- **단독주택은 자동조회 불가.** 공식 오픈API가 없어서, 사용자가 단독주택 주소를
  입력했을 때는 "부동산공시가격알리미(realtyprice.kr)에서 확인 후 직접 입력" 안내로
  넘어가야 합니다. (참고: 검색 중에 "개별주택가격정보" 오픈API가 data.go.kr에 있는
  것도 확인됐는데, 아직 검증은 안 했습니다 — 필요하면 같은 방식으로 검증해서
  추가하면 됩니다.)
- `VWORLD_DOMAIN`을 `localhost`로 등록해도 서버 쪽(파이썬)에서 호출할 때는 문제없이
  동작했습니다 (브라우저 주소창에서 직접 테스트했을 때도 정상 작동 확인).
- 브이월드 API는 `http://` (https 아님) 입니다 — 오타 아닙니다.

## 통합 데모 (frontend/index.html)

`frontend/index.html`은 기존에 만들었던 "우리집 세금계산기"에 주소 자동조회 기능(주소 검색
팝업 + 동/호수 입력 + 공시가격 자동 채우기 + 실거래가 참고 조회)을 붙여넣은 버전입니다.
**탭에 따라 다른 조회 기능이 보입니다**: 종합부동산세 탭에서는 "공시가격 자동 조회"만,
양도소득세 탭에서는 "실거래가 참고 조회"만 보입니다(공시가격은 종부세에만, 실거래가는
양도세에만 쓰이는 값이라서요). 이 파일은 Claude Artifact(게시된 웹페이지)가 아니라
**평범한 HTML 파일**이라서, Artifact의 보안 제약(외부 API 직접 호출 불가) 없이 자유롭게
백엔드를 호출할 수 있습니다.

### 사용 방법

1. 먼저 `backend` 서버를 켜두세요 (위 2단계 그대로):
   ```bash
   cd backend
   uvicorn main:app --reload --port 8000
   ```
2. **`frontend/index.html`을 더블클릭으로 직접 열면 안 됩니다.** (아래 "중요" 참고)
   대신 `frontend` 폴더에서 간단한 로컬 웹서버를 하나 더 띄우세요 (새 명령 프롬프트 창에서):
   ```bash
   cd frontend
   python -m http.server 5500
   ```
3. 브라우저에서 `http://localhost:5500/index.html` 로 접속

**종합부동산세 탭에서**: "주소 검색" → 동·호수 입력 → **"공시가격 불러오기"** 클릭하면
"공시가격" 입력칸이 자동으로 채워지고 계산 결과가 바로 갱신됩니다 (실제 테스트로 확인됨).
동/호수를 안 넣으면 단지 내 여러 세대 중 하나(첫 번째)의 값이 채워지고 경고 문구가 뜹니다.

**양도소득세 탭에서**: 주소 검색 후 두 가지 참고 조회가 가능합니다.
- **"최근 6개월 실거래가 참고 보기"** — 같은 지번(단지)의 최근 거래 내역을 표로 보여줍니다
- **"취득 당시 실거래가 조회"** — 취득시기(YYYYMM)를 입력하면, "이때 취득했는데 얼마였는지
  기억이 안 난다" 싶을 때 그 시점 전후의 실거래 내역을 참고할 수 있습니다

두 표 모두 금액(또는 "적용" 버튼)을 클릭하면 그 금액이 바로 해당 입력칸에 채워집니다 —
"최근 6개월 실거래가 참고 보기"는 양도(매도)가액에, "취득 당시 실거래가 조회"는
취득가액에 (아래 "실거래가 클릭 자동입력" 참고).

"계산 결과" 카드 아래에 **"계산 과정 검증"** 카드가 새로 추가됐습니다. 위에서 입력한
값을 그대로 가져와서, 연도 버튼(2027~2030)을 고르면 "현행 유지 가정"과 "개편안 적용"
각각이 과세표준 → 산출세액(종부세는 구간별 누진세율표까지) → 세액공제/장특공제 →
결정세액까지 어떤 공식과 숫자로 나왔는지, 항목을 클릭하면 펼쳐서 볼 수 있습니다. 기본은
모두 접혀 있고(결과 금액만 한 줄로 보임), "모두 펼치기" 버튼으로 한 번에 펼치거나 접을
수 있습니다. 이 섹션은 로컬 계산이라 백엔드 서버 없이도 작동합니다.

### 종부세 공시가격 상승률 반영 (2026-09-18 추가, 전년도 대비 방식으로 변경)

기존에는 2027~2030년 내내 공시가격이 똑같다고 가정했는데, 실제로는 매년 오르내립니다.
처음에는 상승률을 직접 퍼센트로 입력받게 만들었는데, "전년도 공시가격과 비교해서 상승률
자체를 계산하라"는 피드백에 따라 방식을 바꿨습니다. 종합부동산세 입력 칸에 **"작년(2025년)
공시가격"** 필드를 추가했고, `(올해 공시가격 − 작년 공시가격) ÷ 작년 공시가격`으로 연간
상승률을 직접 계산합니다(예: 작년 1억 → 올해 1억 3천이면 30% 상승). 그 상승률이 2027년부터
그대로 매년 복리로 이어진다고 가정해서(`2027년 = 올해 × (1+상승률)`, `2028년 = 2027년 ×
(1+상승률)`, …) 그 해의 종부세를 계산합니다. 입력 칸 아래에 계산된 상승률이 바로
표시됩니다. **작년보다 올해 공시가격이 하락한 경우에는 그 하락률을 그대로 미래에
투영하지 않고, 0% 상승(가격 유지)으로 계산합니다** — 한 해 하락했다고 계속 떨어진다고
가정하는 건 과도하다는 피드백을 반영했습니다. 양도소득세의 취득가액·양도가액은 여전히
사용자가 실제 계약한 금액이라 이 상승률과 무관하게 그대로 둡니다.

### 올해·작년 공시가격 한 번에 조회 (2026-09-18 추가)

위 상승률 기능이 추가된 뒤에도 "공시가격 불러오기" 버튼은 여전히 **한 해치**(`PRICE_API_YEAR`,
기본값 2026년)만 조회해서 "공시가격" 칸에만 채워주고 있었고, "작년 공시가격" 칸은 자동조회
대상이 아니라 항상 직접 입력해야 했습니다. 이제 `/lookup`이 같은 세대(PNU+동/호) 기준으로
브이월드 API를 **두 번**(올해 `PRICE_API_YEAR`, 작년 `PRICE_API_PREV_YEAR` — 지정하지 않으면
`PRICE_API_YEAR - 1`이 자동으로 쓰임) 호출해서 두 연도 값을 한 번에 내려주고, 프론트엔드는
"공시가격"과 "작년 공시가격" 칸을 버튼 한 번으로 같이 채웁니다. 신축 단지 등으로 작년 데이터가
아예 없는 경우에는(브이월드에 그 연도 데이터가 없음) 올해 값만 채우고 작년 칸은 비워둔 채
상태 메시지로 직접 입력이 필요하다고 안내합니다 — 이 경우에도 올해 값 조회 자체는 그대로
성공 처리되어 요청 전체가 실패하지 않습니다.

### 실거래가 클릭 자동입력 (2026-09-18 추가)

양도소득세 탭의 실거래가 참고 표 두 개 모두, 행(또는 "적용" 버튼)을 클릭하면 그

실행됩니다. 표에 여러 건이 있을 때 사용자가 원하는 실거래 사례를 골라 클릭하기만
하면 되므로, 직접 금액을 타이핑할 필요가 없습니다.

- **"최근 6개월 실거래가 참고 보기"** → 클릭 시 **양도(매도)가액**에 적용
- **"취득 당시 실거래가 조회"** → 클릭 시 **취득가액**에 적용

### 다주택자 보유주택 목록 관리 (2026-09-18 추가)

종부세 탭에서 1세대 2주택·3주택 이상 시나리오를 고르면, 주소 조회 영역 아래에
**"보유주택 목록"** 섹션이 나타납니다. 이 시나리오들에서는 종부세가 "각 주택별로 따로"
계산되는 게 아니라 **보유한 모든 주택의 공시가격을 합산한 금액**을 기준으로 한 번에
계산되기 때문에(다주택자 기본공제도 `4억원 + 5억원 × 실거주 주택 공시가격/보유주택
합계`처럼 합계가 분모로 들어감), 주택별로 공시가격을 따로 모아서 자동으로 더해주는
기능입니다.

- 주소를 입력하고 "공시가격 불러오기"를 누르면(다주택 시나리오에서는 버튼 이름이
  "목록에 추가"로 바뀝니다), 조회된 주택이 입력칸을 덮어쓰는 대신 **목록에 한 채씩
  추가**됩니다. 여러 주소를 순서대로 조회하면 계속 쌓입니다.
- 아파트/연립주택이 아니라 자동조회가 안 되는 단독주택이나, 주소는 알지만 API로 안
  잡히는 경우를 위해 **"직접 입력으로 추가"**(주택 이름/메모 + 공시가격 수동 입력)도
  같이 제공합니다.
- 목록에 있는 주택 중 **"실거주" 라디오 버튼**으로 실제 거주 중인 주택 하나를 고를 수
  있고(기본공제 계산에 필요), 각 행의 **× 버튼**으로 삭제할 수 있습니다.
- 올해 공시가격은 조회 시 자동으로 채워지지만, **작년 공시가격이 없는 주택**(신축 등)은
  목록 행에 입력칸이 바로 나타나서 그 자리에서 직접 채울 수 있습니다(비워두면 그
  주택은 작년 합계에 0원으로 계산됩니다).
- 목록 아래에 "등록된 주택 N채 · 합계 ○○억 · 작년 합계 ○○억"이 실시간으로 표시되고,
  이 합계·실거주 주택 공시가격·작년 합계가 기존 "공시가격"/"작년 공시가격" 입력칸에
  자동으로 반영되어 종부세가 즉시 재계산됩니다. 1주택자 시나리오(`res1`, `nonres1`)는
  원래대로 조회 즉시 입력칸에 바로 채워지는 방식 그대로입니다(주택이 하나뿐이라 목록이
  필요 없음).

### 중요: `file://`로 직접 열면 주소 검색 팝업이 작동하지 않습니다

`index.html`을 더블클릭해서 `file:///...` 로 열면, 주소 입력 자체(공시가격 조회 fetch)는
되지만 **"주소 검색" 팝업(다음 우편번호 서비스)은 작동하지 않습니다.** 브라우저가
`file://` 페이지를 각각 독립된(고립된) 보안 출처로 취급해서, 팝업 내부 통신이 막히기
때문입니다(실제 테스트에서 "Unsafe attempt to load URL file://... 'file:' URLs are treated
as unique security origins" 에러로 확인됨). 반드시 위 2~3번처럼 `python -m http.server`로
`http://localhost:.../index.html` 형태로 열어야 정상 작동합니다. (나중에 실제 서비스로
배포할 때는 어차피 `https://`로 서빙되니 이 문제는 자연히 없어집니다.)

### 알아둘 점

- **취득가액·양도(매도)가액 모두 실거래가 표에서 클릭하면 자동으로 채워집니다** (위
  "실거래가 클릭 자동입력" 참고). 다만 이 표들은 "그 시기/최근에 이 정도에 거래되더라"
  하는 참고 시세일 뿐, 사용자 본인이 실제로 계약한 금액과 다를 수 있습니다. 채워진
  값이 실제 계약서 금액과 다르면 반드시 직접 수정해서 입력해야 합니다.
- 이 데모는 백엔드가 `localhost:8000`에서 켜져 있다는 가정으로 만들어졌습니다. 백엔드
  서버와 (`http.server`로 띄운) 프론트엔드 서버, 둘 다 같은 컴퓨터에서 동시에 실행돼야
  합니다 (명령 프롬프트 창 2개가 각각 켜져 있어야 함).
- 나중에 실제 서비스로 배포할 때는, 이 파일의 `BACKEND_URL` 값(`http://localhost:8000`)을
  실제 배포된 백엔드 주소로 바꾸면 됩니다.

  프론트엔드(웹이든 앱이든)에서 호출하는 구조가 되어야 합니다.

- 실제 배포 시에는 `VWORLD_DOMAIN`을 실제 서비스 도메인으로 바꾸고, 브이월드
  인증키 신청 시 등록한 서비스URL도 함께 갱신하는 게 안전합니다.
